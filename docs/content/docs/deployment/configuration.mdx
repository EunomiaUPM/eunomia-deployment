## Image versions: versions.env

[`versions.env`](https://github.com/EunomiaUPM/eunomia-deployment/blob/main/versions.env) is the **only** place the EUNOMIA images are pinned:

```dotenv
EUNOMIA_IMAGE=quay.io/eunomia_upm/ds-agent
EUNOMIA_TAG=v0.4.0
HEIMDALL_IMAGE=quay.io/eunomia_upm/heimdall
HEIMDALL_TAG=v1.5.0
FAFNIR_IMAGE=quay.io/eunomia_upm/fafnir-wallet
FAFNIR_TAG=v0.2.0
```

Every compose file reads it (the CLI passes `--env-file versions.env`). Change a tag and run `./eunomia up` again. `./eunomia images --check` lists newer tags in the registries, without applying them: check what a tag contains before bumping it.

Infrastructure images (Postgres, Redis, Keycloak) are pinned in the compose files.

## Settings: .env

The CLI reads `.env` at the repo root (copy [`.env.example`](https://github.com/EunomiaUPM/eunomia-deployment/blob/main/.env.example)); anything exported in the shell wins. Standalone needs none of it.

| Variable | Default | What |
| --- | --- | --- |
| `EUNOMIA_PREFIX` | `eunomia` | prefix of every container and compose project |
| `EUNOMIA_AUTHORITY_DB_PORT`, `…_PROVIDER_DB_PORT`, `…_CONSUMER_DB_PORT` | `1450`, `1400`, `1300` | host ports of the databases |
| `EUNOMIA_FACTORY_STATIC_PORT`, `…_DYNAMIC_PORT`, `…_KEYCLOAK_PORT` | `1210`, `1220`, `1230` | host ports of the demo factory |
| `EUNOMIA_SINK_PORT` | `1290` | where `e2e` and `demo events` receive pushed events |
| `EUNOMIA_HTTP_PORTS`, `EUNOMIA_DB_PORTS` | `1600-1999`, `15400-15999` | port ranges of extra participants |
| `EUNOMIA_PUSH_TIMEOUT` | `30` | seconds `e2e` waits for a pushed event |
| `EUNOMIA_CONTAINER` | | `1`: run the CLI in its container even with Python on the machine |
| `AUTHORITY_URL`, `PROVIDER_URL`, `CONSUMER_URL` | standalone: `http://127.0.0.1:<port>` | how the CLI reaches each agent; required in prod |
| `DOCKER_AUTHORITY_URL`, … | standalone: `http://host.docker.internal:<port>` | how the agents reach each other |
| `DOCKER_FACTORY_STATIC_URL`, … | `http://host.docker.internal:<port>` | where the provider agent reaches the demo factory |
| `<NODE>_SSH_*`, `<NODE>_PATH` | | prod: SSH access for `eunomia restart` |

The agent ports, 1100, 1200 and 1500, are fixed in standalone: each participant advertises its own address to the others, from its configuration. For participants on other ports, use [extra participants](/docs/deployment/instances).

## Participant configuration: static/config

| File | What |
| --- | --- |
| `static/config/provider/standalone/standalone.provider.yaml` | the provider agent |
| `static/config/consumer/standalone/standalone.consumer.yaml` | the consumer agent |
| `static/config/heimdall/standalone/standalone.eco_authority.yaml` | the authority (eco role: also Gaia-X) |
| `static/config/heimdall/standalone/standalone.authority.yaml` | an authority with the dataspace role only |
| `static/config/*/standalone/fafnir.*.yaml` | each wallet |
| `static/config/*/prod/` | the same for prod |

Things you may want to change:

- **What a provider asks of consumers**: `ssi_auth.verify_req_config.vcs_requested` in the provider's file. Standalone asks for `gx:labelcredential`; `DataSpaceParticipant` only needs registration.
- **The Gaia-X legal person**: `ssi_auth.gaia_config.legal_person`. The VAT number the authority certifies comes from the certificate, not from here: `organizationIdentifier` in `vault/<participant>/secrets/cert.pem.example`.
- **The DID method**: `did_config.type`. Keep `Jwk` in standalone ([why](/docs/architecture/trust#identifiers)).

Keep the hostnames (`provider-db`, `provider-redis`, `provider-fafnir-wallet`, …) and ports as they are: they match the compose files, and the extra participants are generated from these files by replacing them.

Configuration is read at start: after a change, `./eunomia down` and `./eunomia up` to start from a clean state, or `docker compose … up -d --force-recreate <service>` for one service.

## Example identities: vault

`vault/<participant>/secrets/` holds the committed example keys and certificates (`*.pem.example`) and the database credentials (`db.json.example`, matching `static/envs/<participant>/db.env.example`). They are for local use only. The certificates are self-signed and valid until June 2027.

## Catalog: static/catalog

The JSON payloads `./eunomia catalog populate` sends to the provider, in order. `__PLACEHOLDERS__` are filled with the ids the provider returns and the factory URLs. See [The demo factory](/docs/components/demo-factory#in-the-catalog).
