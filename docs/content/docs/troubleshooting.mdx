---
title: "Troubleshooting"
description: "Frequent problems, what causes them and how to fix them."
---

Start with `./eunomia doctor`, then `./eunomia status`, and look at the logs of whatever is not ready: `./eunomia logs <instance>`, `./eunomia logs demo`, or `./eunomia logs <container>` for a single container. The one-shot `*-setup` containers end in `exited`; if one fails, its log says why.

## Starting

| Symptom | Cause and fix |
| --- | --- |
| `Docker is installed but not answering` | Start Docker Desktop (or `sudo systemctl start docker`) and wait until it is running. |
| `Ports … are in use` or `No free port` | Something else holds the demo ports, or the start of the instance ranges. Stop it, or move them in `.env` (see [Configuration](/docs/deployment/configuration)). An existing instance keeps its ports: remove and recreate it to move it. |
| `These ports are held by processes outside Docker` | A native process (an agent built locally, a dev server) on a deployment port. It would answer on `127.0.0.1` while the container looks healthy. Stop it. |
| An instance never becomes healthy | `./eunomia logs <instance>`. On Apple Silicon the amd64 images are emulated and the first start is slow; run `./eunomia up` again. |
| Image pull fails | Check your connection and the tags in `versions.env`; `./eunomia doctor --images` checks them all. |
| Setup job fails with a permission error on `vault/` (Linux) | The setup jobs write into `instances/<name>/vault/secrets`. `./eunomia up` makes it writable; if you started compose by hand, `chmod -R a+rwX instances`. |

## Onboarding

| Symptom | Cause and fix |
| --- | --- |
| Onboarding times out on Linux | The firewall (ufw, firewalld) blocks containers from reaching the host at `host.docker.internal`. Allow the `docker0` interface. |
| A credential stays `Approved` or `Pending`, never `Finalized` | `./eunomia logs authority`. For `gx:VatId`: the participant certificate needs an `organizationIdentifier` with a VAT number, and the authority needs the eco role. |
| The connection stays `Pending` | The agent you connect to asks for `gx:LabelCredential` and yours lacks it: `./eunomia onboard <agent>` with an eco authority. |
| `502` from an agent on any DSP call | It holds no token for the agent it calls: the GNAP login never completed. `./eunomia login <agent> <other>`. |
| `Mate not found` on the catalog request | The agents use `did:web` on `host.docker.internal`: the port in the DID breaks the lookup. Use `did:jwk` for local instances (`did_config.type: Jwk`). |
| Everything breaks after June 2027 | The example certificates in `vault/*/secrets/cert.pem.example` expire then. Regenerate them, keeping the `organizationIdentifier`. |

## Instances

| Symptom | Cause and fix |
| --- | --- |
| `There is no instance called …` | `./eunomia ls` lists the names. Instances are created with `authority add` and `agent add`, never by `up`. |
| `There is no authority yet` / `several authorities` | Create one with `./eunomia authority add <name>`, or say which with `--authority <name>`. |
| An agent keeps old credentials after its authority was removed | Its records outlive the authority's database. Remove the agent and create it again. |

## Exchanging data

| Symptom | Cause and fix |
| --- | --- |
| `The catalog of … is empty` | Nothing published there yet: `./eunomia demo publish <agent>`. |
| The data plane proxy answers an error | The provider agent could not reach the factory: is it up (`./eunomia demo up`)? Then `./eunomia logs <provider agent>`. |
| `No event reached :1290` | `./eunomia logs demo`, and the logs of both agents. Port 1290 must be free (`EUNOMIA_SINK_PORT` to move it), and on Linux the firewall must let containers reach the host. |
| `Cannot listen on port 1290` | Another `demo test` or `demo events` is running, or something else uses the port: set `EUNOMIA_SINK_PORT`. |
| Every event type arrives, not just the one subscribed to | That is how the demo factory behaves: it sends every event to every subscriber. |

## Starting over

```bash
./eunomia down --yes    # every local instance, its data and identity, and the demo
./eunomia authority add authority
./eunomia agent add alice
```

For one instance: `./eunomia rm <name> --yes` and create it again.
