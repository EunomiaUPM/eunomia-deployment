---
title: "The demo factory"
description: "A data backend any agent can share: a factory with robots, their yearly measures and the events they emit."
---

The demo factory is a data backend any agent can share: a fleet of robots, a year of production figures for each, and a stream of events the robots emit. It is a small Go service in [`extensions/demo/service/`](https://github.com/EunomiaUPM/eunomia-deployment/tree/main/extensions/demo/service), with its own Postgres and a Keycloak in front, started with `./eunomia demo up` and published by an agent with `./eunomia demo publish <agent>`. Several agents can publish it at once.

The agent that publishes it sits in front of it: the agents that consume it never call it directly, and never see its credentials.

## Pull: the robots

The **static API** ([http://127.0.0.1:1210/docs](http://127.0.0.1:1210/docs)) serves the robots and their measures:

| Route | Returns |
| --- | --- |
| `GET /robots/` | every robot with its measures |
| `GET /robots/{id}` | one robot with its measures |
| `GET /robots/{id}/measures` | the yearly measures of one robot |
| `GET /measures/{id}` | one measure |
| `POST /robots/`, `POST /measures/` | create one |

A robot:

```json
{
  "name": "Helix",
  "model": "KR-210 Quantec",
  "line": "Line A",
  "measures": [
    {
      "robot_id": 1,
      "year": 2025,
      "cycles": 1250000,
      "uptimeHours": 7900.5,
      "downtimeHours": 310.2,
      "energyKwh": 23150.4,
      "partsProduced": 1180000,
      "defectRate": 0.012,
      "oee": 0.84,
      "mtbfHours": 3200,
      "maintenanceCount": 9,
      "avgTemperatureC": 44.7
    }
  ]
}
```

On first start it seeds five robots with four years of measures each.

## Push: the robot events

The **dynamic API** ([http://127.0.0.1:1220/docs](http://127.0.0.1:1220/docs)) takes subscriptions and pushes events to them:

| Route | Does |
| --- | --- |
| `POST /subscriptions/subscribe` | `{"url": "<where to POST>", "event_type": "robot_temperature"}`; answers `{"data": {"ID": 3, …}}` |
| `POST /subscriptions/unsubscribe/{id}` | cancels it |

Every 3 seconds a simulator updates four event types, `robot_temperature`, `robot_energy_usage`, `robot_cycle_time` and `robot_vibration`, and POSTs each to every subscriber:

```json
{ "id": 3, "item_type": "robot_temperature", "last_value": 47.3, "last_measured_at": "2026-10-20T00:00:00Z" }
```

Every subscriber gets every event type, whatever `event_type` it subscribed with, and `last_measured_at` carries the day only.

## Authentication

Every route except `/docs` and `/openapi.yaml` needs a bearer token from the factory's Keycloak ([http://127.0.0.1:1230](http://127.0.0.1:1230), realm `factory`). These are demo credentials:

| | |
| --- | --- |
| Client | `factory-client` / `factory-secret` |
| User | `testuser` / `password` |
| Keycloak admin | `admin` / `admin` |

`./eunomia demo token` prints a token, to call the API yourself:

```bash
TOKEN=$(./eunomia demo token)
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:1210/robots/
```

The publishing agent does the same thing on its own: its connectors use the OAuth2 password grant against this Keycloak, and refresh the token when it expires.

## In the catalog

`./eunomia demo publish <agent>` creates in that agent's catalog, from [`extensions/demo/payloads/`](https://github.com/EunomiaUPM/eunomia-deployment/tree/main/extensions/demo/payloads):

```text
Dataset: Factory Robots Dataset
├── Distribution: HTTP Pull   → GET /robots/
├── Distribution: HTTP Push   → robot events
├── Policies
│   ├── template instantiation: research access for UPM
│   ├── commercial use with attribution (2026-2030)
│   └── research trial: read only, 10 000 requests (2026-2028)
├── Connector template: HTTP Pull (OAuth2 password grant)
├── Connector template: HTTP Push (OAuth2 password grant, EVENT_TYPE parameter)
└── Connector instances
    ├── pull → http://host.docker.internal:1210/robots/
    └── push → http://host.docker.internal:1220/subscriptions/subscribe, …/unsubscribe/{id}
```

The connector URLs are the ones the **publishing agent** uses, from its container. The push template subscribes with that agent's own ingress URL, and takes the subscription id for the unsubscribe from the subscribe response (`{.subscription.data.ID}`).

## Developing it

```bash
cd extensions/demo/service
go build ./...
docker compose --env-file ../../../versions.env up -d --build   # or: ./eunomia demo up --build
```

The specs are in `extensions/demo/service/specs/`: OpenAPI (also served at `/openapi.yaml`), protobuf and Postman collections.
