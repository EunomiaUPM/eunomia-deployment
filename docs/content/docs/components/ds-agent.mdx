[DS-Agent](https://github.com/EunomiaUPM/ds-agent) is what a participant runs to take part in the data space. Every agent is the same: it **publishes a catalog**, **browses other agents' catalogs**, **negotiates contracts** in both directions and **moves data** through its data plane. In each exchange one agent plays the provider (its catalog is used) and the other the consumer (it negotiates for it); the next exchange can swap them.

## What it does

- **SSI authentication**: links its wallet, requests credentials from authorities, and opens and approves GNAP grants with peers, checking the credentials it requires.
- **Catalog**: a DCAT 3 catalog of datasets, data services and distributions, with ODRL policies and policy templates, served over the Dataspace Protocol catalog API.
- **Contract negotiation**: the full DSP negotiation state machine, from both sides.
- **Transfers**: the DSP transfer process, and the data plane that runs it: an HTTP proxy for pull, an ingress for push, driven by connector templates and instances.
- **Admin console**: a web UI at `/admin/login` (locally: `eunomia` / `eunomia`) to do all of the above by hand.

## Inside

The agent is a Rust workspace; the `monolith` crate builds the binary that runs every module in one process.

| Crate | Responsibility |
| --- | --- |
| `monolith` | the binary: `setup` and `start`, routing every module |
| `common` | shared types, configuration, errors |
| `auth` | wallet link, credential requests, GNAP peer connections, mates |
| `catalog-agent` | DCAT catalog, datasets, distributions, data services, ODRL policies and templates |
| `negotiation-agent` | DSP contract negotiation |
| `transfer-agent` | DSP transfer processes |
| `dataplane` | the data plane: proxy for pull, ingress for push |
| `connector` | connector templates and instances, the bridge to backends |
| `keystore` | keys |
| `events` | events between modules |
| `bff` | the gateway the admin console talks to |

It is built on [Ymir](/docs/components/ymir) for its identity and protocol types, and talks to its [Fafnir](/docs/components/fafnir) wallet over HTTP.

## Running it

The image takes two commands, each with the configuration file:

```yaml
agent-setup:
  image: "${EUNOMIA_IMAGE}:${EUNOMIA_TAG}"
  command: ["setup", "-e", "/app/static/config/agent.yaml"]   # migrations, identity material
agent:
  image: "${EUNOMIA_IMAGE}:${EUNOMIA_TAG}"
  command: ["start", "-e", "/app/static/config/agent.yaml"]   # serve
```

That is the agent template in [`deployment/instances/`](https://github.com/EunomiaUPM/eunomia-deployment/blob/main/deployment/instances/docker-compose.agent.yaml). It also reads the env file `static/envs/agent/core.env.example`, which points it at its vault and the secret files in it.

| Needs | In a local instance |
| --- | --- |
| PostgreSQL | `db` |
| Redis (cache) | `redis` |
| A Fafnir wallet | `wallet` |
| A vault | `instances/<name>/vault/`, file based |
| OpenAPI specs | `static/specs/agent/`, mounted at `/app/static/specs` |
| Policy templates | `static/policy_templates/` |

## Configuration

One YAML file, with YAML anchors to share the common blocks. Local agents get theirs from [`agent.template.yaml`](https://github.com/EunomiaUPM/eunomia-deployment/blob/main/static/config/agent/standalone/agent.template.yaml), with their name, port and identity filled in, in `instances/<name>/config/agent.yaml`; production uses [`core.agent.yaml`](https://github.com/EunomiaUPM/eunomia-deployment/blob/main/static/config/agent/prod/core.agent.yaml).

## API

| Prefix | What |
| --- | --- |
| `/api/v1/...` | management: wallet, credentials, peer connections, mates, catalog, connectors, negotiations, transfers |
| `/dsp/current/...` | the Dataspace Protocol, and its RPC layer `…/rpc/setup-*` |
| `/dataplane/...` | the data plane |
| `/.well-known/did.json`, `/.well-known/dspace-version` | discovery |
| `/admin/...` | the console |

The full spec is in [API reference → Agent](/docs/api). The calls you need most are in [Onboarding](/docs/architecture/onboarding) and [Exchanging data](/docs/guides/data-exchange).

## Health

`GET /api/v1/readiness` answers 200 once the agent is up; the compose healthcheck and `eunomia status` use it.
