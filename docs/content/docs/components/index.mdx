## How they fit

```text
         ┌───────────────┐
         │   Heimdall    │──── Fafnir ─── Postgres
         └───────┬───────┘
     credentials │ (OID4VCI / OID4VP, GNAP)
      ┌──────────┴───────────┐
┌─────┴─────┐          ┌─────┴─────┐
│ DS-Agent  │◄── DSP ─►│ DS-Agent  │   any number of agents,
│  alice    │          │   bob     │   each with Fafnir,
└─────┬─────┘          └─────┬─────┘   Postgres and Redis
      │ data plane           │
┌─────┴─────┐          ┌─────┴─────┐
│ backend   │          │ backend   │
└───────────┘          └───────────┘
```

Every node is a set of containers in its own compose project:

| Node | Containers |
| --- | --- |
| Authority | Heimdall, Fafnir wallet, Postgres, and one-shot `setup` jobs for both |
| Agent | DS-Agent, Fafnir wallet, Postgres, Redis, and one-shot `setup` jobs |

The `setup` jobs run the database migrations and derive the identity material from the vault, then exit. The long-running services start once they succeed.

## Common traits

- **Rust**, on Tokio, with Axum for HTTP and SeaORM on PostgreSQL.
- **Configured by one YAML file**, passed with `-e` / `--env-file`, plus env files for the vault. The templates for local instances, and the production files, live in [`static/config/`](https://github.com/EunomiaUPM/eunomia-deployment/tree/main/static/config).
- **Two commands**: `setup` (migrate and prepare) and `start` (serve).
- **amd64 images**. On Apple Silicon Docker Desktop runs them under emulation.
