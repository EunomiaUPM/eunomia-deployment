A **data space** is a network where organisations share data under rules they agree on: who may use it, for what, until when. Every participant proves who it is with verifiable credentials, every exchange starts with a contract, and the data travels through the provider's own connector, never around it.

**EUNOMIA** builds data spaces from open standards (the Dataspace Protocol, ODRL, GNAP, OpenID for Verifiable Credentials, W3C Verifiable Credentials) with a small set of Rust components, and this repository deploys them. On one machine, three commands give you an authority, a provider and a consumer, onboarded and connected, and a demo factory whose robots the provider shares:

```bash
./eunomia doctor   # check Docker, ports and versions
./eunomia up       # start, onboard, populate the catalog
./eunomia e2e      # negotiate a contract, pull the robots, receive their events
```

## What you get

- **An authority** ([Heimdall](/docs/components/heimdall)) that onboards participants and issues their credentials, Gaia-X ones included.
- **Agents** ([DS-Agent](/docs/components/ds-agent)) that publish catalogs, negotiate ODRL contracts and move data over the Dataspace Protocol, pulled on demand or pushed as events.
- **A wallet** ([Fafnir](/docs/components/fafnir)) next to each of them, holding its keys, DID and credentials.
- **A demo backend** ([the factory](/docs/components/demo-factory)) with robots to pull and robot events to stream.
- **One CLI** ([`eunomia`](/docs/cli)) that starts, onboards, tests and inspects all of it, and adds more participants on demand.
