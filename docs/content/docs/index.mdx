A **data space** is a network where organisations share data under rules they agree on: who may use it, for what, until when. Every participant proves who it is with verifiable credentials, every exchange starts with a contract, and the data travels through the agent of whoever owns it, never around it.

**EUNOMIA** builds data spaces from open standards (the Dataspace Protocol, ODRL, GNAP, OpenID for Verifiable Credentials, W3C Verifiable Credentials) with a small set of Rust components, and this repository deploys them. On one machine, a handful of commands give you an authority and as many agents as you want, onboarded, and a demo factory full of robots any agent can share:

```bash
./eunomia authority add authority                    # an authority
./eunomia agent add alice                            # two agents, onboarded with it
./eunomia agent add bob
./eunomia demo up                                    # a backend full of robots
./eunomia demo publish alice                         # alice publishes it
./eunomia demo test --consumer bob --provider alice  # bob negotiates, pulls and streams
```

## What you get

- **An authority** ([Heimdall](/docs/components/heimdall)) that onboards participants and issues their credentials, Gaia-X ones included.
- **Agents** ([DS-Agent](/docs/components/ds-agent)), all alike: each one can publish a catalog, negotiate ODRL contracts with any other and move data over the Dataspace Protocol, pulled on demand or pushed as events.
- **A wallet** ([Fafnir](/docs/components/fafnir)) next to each of them, holding its keys, DID and credentials.
- **A demo backend** ([the factory](/docs/components/demo-factory)) with robots to pull and robot events to stream.
- **One CLI** ([`eunomia`](/docs/cli)) that works as a hypervisor: it creates, starts, onboards, connects and removes authorities and agents by name, on this machine or on servers.
