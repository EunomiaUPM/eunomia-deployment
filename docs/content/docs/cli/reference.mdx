Run it as `./eunomia <command>` (macOS, Linux) or `.\eunomia.cmd <command>` (Windows), or `eunomia` after `pip install -e .`. Every command takes `--help`. For the commands in context, see [Workflows](/docs/cli/workflows).

<Callout type="info">This page is generated from the CLI itself: `python3 cli/tools/gen_cli_docs.py`. CI fails when it is out of date.</Callout>

## `eunomia doctor`

Check Docker, Compose, ports and versions.env.

```text
eunomia doctor [-h] [--images]

options:
  -h, --help  show this help message and exit
  --images    also check every pinned image can be pulled
```

## `eunomia authority`

Authorities: issue credentials and admit agents.

### `eunomia authority add`

Create and start an authority on free ports.

```text
eunomia authority add [-h] [--role {eco,dataspace}] [name]

positional arguments:
  name                  default: authority-<random>

options:
  -h, --help            show this help message and exit
  --role {eco,dataspace}
                        eco (default) also issues Gaia-X credentials
```

## `eunomia agent`

Agents: publish catalogs, negotiate, exchange data.

### `eunomia agent add`

Create and start an agent on free ports, and onboard it.

```text
eunomia agent add [-h] [--authority AUTHORITY] [--no-onboard] [name]

positional arguments:
  name                  default: agent-<random>

options:
  -h, --help            show this help message and exit
  --authority AUTHORITY
                        onboard it with this authority (default: the only one there is)
  --no-onboard          only create and start it
```

## `eunomia remote`

Instances running on other servers, known by URL.

### `eunomia remote add`

Register a remote authority or agent.

```text
eunomia remote add [-h] --kind {agent,authority} --url URL [--ssh USER@HOST] [--path PATH]
                          name

positional arguments:
  name

options:
  -h, --help            show this help message and exit
  --kind {agent,authority}
  --url URL             its public URL, e.g. https://agent.example.org
  --ssh USER@HOST       SSH access, for eunomia restart
  --path PATH           its deployment/prod directory on the server, for eunomia restart
```

```text

positional arguments:
  target        an instance name, a service name ('demo'), or a container name
  services      limit to these compose services
```

```text
  -h, --help  show this help message and exit
```

### `eunomia demo test`

The demo extension's end-to-end test between two agents.

```text
eunomia demo test [-h] --consumer AGENT --provider AGENT [--dataset DATASET]
                         [--list-datasets] [--keep-open] [--no-suspend] [--no-data-pull]
                         [--no-push] [-v]

options:
  -h, --help         show this help message and exit
  --consumer AGENT   the agent that negotiates and receives
  --provider AGENT   the agent whose catalog is used
  --dataset DATASET  substring of the dataset title (default: the demo factory dataset)
  --list-datasets    list the provider's catalog and exit
  --keep-open        leave the pull transfer STARTED
  --no-suspend       skip the suspend/resume leg
  --no-data-pull     skip the data pull through the proxy
  --no-push          skip the push transfer
  -v, --verbose      dump every request and response
```

### `eunomia demo notebook`

The notebooks, with one agent as the provider and another as the consumer.

```text
eunomia demo notebook [-h] [--execute] [--flow {pull,push}] [--no-browser] [--fresh]
                             provider consumer

positional arguments:
  provider            the agent that publishes
  consumer            the agent that negotiates and receives

options:
  -h, --help          show this help message and exit
  --execute           run the flows headless instead of opening JupyterLab
  --flow {pull,push}  with --execute, only this flow (repeatable)
  --no-browser        start JupyterLab without opening a browser
  --fresh             copy every source notebook into the session again, dropping its outputs and
                      edits
```
