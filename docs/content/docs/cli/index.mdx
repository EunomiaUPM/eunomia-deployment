---
title: "The eunomia CLI"
description: "A hypervisor for EUNOMIA: it creates, starts, onboards, connects and removes authorities and agents by name, on this machine or on servers."
---

`eunomia` manages **instances**: authorities and agents. You create them by name; it gives each one free ports, its own containers, database, wallet and identity, and keeps a registry of them. Every other command (onboarding, connecting, publishing a catalog, exchanging data) takes instances by name, whether they run here or on a server.

It checks the result of every step and says what to look at when one fails.

## Running it

| macOS, Linux | Windows |
| --- | --- |
| `./eunomia <command>` | `.\eunomia.cmd <command>` |

The launcher uses the local **Python 3.8+** when there is one (standard library only, nothing to install). Without Python it builds a small image the first time, [`deployment/tools/`](https://github.com/EunomiaUPM/eunomia-deployment/tree/main/deployment/tools), with Python and the Docker CLI, and runs the CLI inside it with this checkout mounted. So **Docker is the only requirement**. `EUNOMIA_CONTAINER=1` forces the container.

To have `eunomia` on your `PATH`: `pip install -e .` from the repository root.

Every command takes `--help`; the [reference](/docs/cli/reference) lists them all.

## The commands at a glance

| Group | Commands |
| --- | --- |
| Check | `doctor` |
| Create instances | `authority add`, `agent add`, `remote add` |
| Run them | `ls`, `status`, `up`, `stop`, `rm`, `down`, `logs`, `restart` |
| Trust | `onboard`, `connect` |
| Data | `catalog populate\|show`, `e2e`, `demo up\|down\|robots\|events\|token` |
| Production | `prod up\|status\|logs`, `images` |

## Conventions

- **Instances by name.** Names are lowercase letters, digits and dashes. `authority add` and `agent add` pick a random one if you give none.
- **Agents are all alike.** There is no provider or consumer kind of agent. Where a command needs the two roles of an exchange, it asks for them: `e2e --consumer bob --provider alice`.
- **Nothing is implicit.** `up` starts the instances you created and never creates any; catalogs are loaded into the agent you name. The one convenience: when there is a single authority, `agent add` and `onboard` use it.
- **Idempotent.** `onboard`, `connect` and `catalog populate` check first and skip what is done, so running them again is how you resume.
- **Settings** come from the shell and from `.env` at the repository root; nothing is required. See [Configuration](/docs/deployment/configuration).
- **Output.** Progress goes to stderr; data (`demo robots`, `demo token`, `catalog show`, `ls`) goes to stdout, so it pipes cleanly.
- **Exit codes.** `0` on success, `1` on a failed step (with the reason), `130` on Ctrl+C. `status` exits `1` when an instance is not healthy.
